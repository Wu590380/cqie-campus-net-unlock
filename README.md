# CQIE 校园网设备限制解除（Dr.COM eportal + 路由器 NAT）

> 让**路由器**以「一台设备」的身份通过重庆工程学院（CQIE）校园网认证，之后内网所有设备走路由器的 NAT 共享 —— 校方侧只会看到**路由器一个 WAN 侧 MAC**，账号「同时 2 台设备」的配额始终只占 1 个。
>
> **不刷机、不改固件、不碰系统路由表。** 本文结论全部来自 2026-10 在真实环境的实测，凡未实测的部分都会明确标注「未验证」。

---

## ⚠️ 先读这一段

- 本仓库只针对**你自己的账号、你自己的路由器**，不涉及破解他人账号、不入侵任何系统。
- 用一台路由器共享一个账号给多台设备，**很可能违反学校《校园网用户协议》或运营商的入网条款**；由此导致的限速、封号、纪律处分等风险由你自己承担。
- 文中所有个人数据（**学号、密码、MAC、校园网分配到的 IP**）**已脱敏**；脚本从配置文件或环境变量读取你自己的凭据。
- 校内资源（图书馆、教务等）**不需要认证**，直接访问就行，本方案解决的是**出公网**。

## 1. 实测结论（TL;DR）

| 项目 | 实测结果 |
|---|---|
| 门户类型 | **Dr.COM eportal**（`/eportal/index.jsp`、`/eportal/InterFace.do?method=*`），未认证时 http 流量被强制劫持 |
| 认证粒度 | **WAN 侧 MAC + IP**。在线会话回执里 `userMac` = 路由器 MAC，`userIp` = 校园网分配给路由器 WAN 的 10.x 地址 |
| 账号策略 | 门户公告原文：**「每个账户可以同时使用2个设备」** |
| 解除设备数限制的方式 | **路由器 NAT** → 一个账号认证一次 → 校方只看见 1 台设备，后面挂多少台都行（前提：未触发 DPI 多设备检测，见 [docs/03](docs/03-detection-and-risks.md)） |
| 需要刷机吗 | **不需要**。方案完全在原生固件上完成（实测机型：小米路由器 4C，任何支持 DHCP WAN + NAT 的路由器都行） |
| 掉线保活 | 回执 `keepaliveInterval = 0`，即门户不要求客户端保活；掉线后重新认证即可（脚本 `watch` 模式） |
| 未验证 | 多台设备同时在线会不会被 DPI 识别（我们只做了单机实测）；见 [docs/03](docs/03-detection-and-risks.md) |

## 2. 原理（也就是「根据」）

### 2.1 设备限制是在哪一层数的

校园网的「设备数」不是在你的电脑上数的，而是在**认证网关侧**数**在线会话**：每完成一次门户认证，网关就为「一个 WAN 侧 MAC + IP」建立一个会话（回执里的 `userIndex` 就是这次会话的标识）。账号配额限制的是**并发会话数**。

### 2.2 为什么 NAT 之后就只占 1 个名额

路由器做 NAT 以后，内网所有设备的流量在出口都**改写成同一个 WAN 侧地址和同一个 MAC**——校方的网关、日志、配额计数里永远只有路由器这一台设备。所以：

```
[N 台设备] --LAN--> [路由器 NAT] --WAN(1 个 MAC/IP)--> [校园网网关：只数到 1 台]
```

关键点：**认证发生在路由器上，而不是在每台终端上**。手机、电脑、平板连路由器的 Wi-Fi 或 LAN 口时，它们自己不登录门户，网关也看不到它们的 MAC。

### 2.3 三条硬证据

| 证据 | 实测内容 | 说明 |
|---|---|---|
| 在线会话回执 | `getOnlineUserInfo` 返回 `userMac` = **路由器 MAC**、`userIp` = **校园网分配的路由器 WAN IP** | 认证的主体是路由器，不是终端 |
| 认证回执 `userIndex` | 十六进制解码 = `<nasip>_<WAN侧IP>_<账号>` | 网关按「接入点 + WAN 侧 IP + 账号」建会话 |
| 双路径出口 IP | 路由器线出口 `183.69.x.x`（校园网出口） ≠ 手机共享线出口 `123.147.x.x` | 路由器走的是校园网，与手机流量互不相干 |

> 完整的协议细节、回执样例见 [docs/01-portal-protocol.md](docs/01-portal-protocol.md)、[evidence/](evidence/)。

## 3. 前置条件

1. **一台能 NAT 的路由器**。实测：小米路由器 4C（MT7628，百兆，原厂固件，**不刷机**）。
2. **接线**：校园网墙口（网线）→ 路由器 **WAN 口**（蓝口，别接错）；你的电脑/手机 → 路由器 **LAN 口 / Wi-Fi**。
3. **你自己的校园网账号密码**。门户公告写明：*「本认证系统使用学校智慧校园平台统一的用户名和密码」*，忘记密码去 `http://i.cqie.edu.cn/` 重置 —— 也就是说，**它不是路由器后台密码**，别搞混。
4. Python 3.7+（只有用脚本时才需要，纯标准库，无需 pip 安装任何东西）。

## 4. 详细步骤

### Step 1 接线 + 路由器 WAN 设为 DHCP

1. 校园网那根网线插路由器 **WAN 口**；电脑插 **LAN 口**（或用 Wi-Fi）。
2. 浏览器进路由器后台（小米 4C 是 `192.168.31.1`）→ **常用设置 → 上网设置**：
   - 上网方式选 **DHCP / 自动获取 IP**；
   - 看是否显示「**已获取 IP**」，拿到的一般是 `10.x.x.x`（校园网地址段）。
3. 拿不到 IP？两种常见原因：
   - 墙口**按 MAC 放行/绑定**：在同一个页面用 **MAC 克隆**，克隆成你之前能上网那台设备的 MAC；
   - 线接错口（把校园网线插进了 LAN 口）或线本身有问题。

> 这一步做完只是「WAN 拿到了校园网 IP」，还**没有**通过认证 —— 此时路由器仍上不了公网。

### Step 2 触发门户跳转，拿到认证参数

用路由器下面的电脑（或手机连它的 Wi-Fi）访问任意 **http** 站点，例如 `http://www.baidu.com`。

未认证时会被劫持到门户，形如：

```
http://10.253.3.84/eportal/index.jsp
    ?wlanuserip=<hex>            # 认证客户端的 WAN 侧 IP
    &wlanacname=<hex>            # 接入设备名
    &ssid=<hex>
    &nasip=<hex>                 # 网关/接入点标识
    &mac=<hex>                   # 认证客户端的 WAN 侧 MAC
    &t=wireless-v2
    &url=<hex>                   # 原始访问目标
```

这些参数**由门户下发，认证时必须原样回传**（`queryString` 字段）。页标题就是「**上网认证**」。

### Step 3 完成认证

**方式 A：浏览器手动登录**
在认证页输入账号密码（服务选「系统默认服务」），点登录即可。

**方式 B：脚本自动认证（推荐，可反复用）**

```bash
cd scripts
cp config.example.json config.local.json   # 填你自己的账号密码
python eportal_login.py login --config config.local.json
```

成功回执（脱敏样例）：

```json
{
  "userIndex": "<hex>_<_>_<_>",
  "result": "success",
  "forwordurl": null,
  "keepaliveInterval": 0,
  "validCodeUrl": ""
}
```

脚本会自动：探测门户跳转 → 打开认证页拿 `JSESSIONID` → 取服务列表 → **双重编码**后 POST 登录 → 打印 `userIndex` 解码结果。

> **最容易踩的坑**：这个门户要求所有字段**双重 `encodeURIComponent`**。
> 只编一层 → 服务端返回 `密码不匹配,请输入正确的密码!`（我一开始就栽在这，浪费了一次尝试）。
> 详见 [docs/01-portal-protocol.md](docs/01-portal-protocol.md#双重编码这个门户最容易踩的坑)。

### Step 4 验证认证真的生效了

```bash
# 1) 联网探针：期望 204
curl -s -o /dev/null -w "%{http_code}\n" http://connect.rom.miui.com/generate_204

# 2) 看出口公网 IP（认证前这里会返回一段劫持脚本，认证后才返回 IP）
curl -s http://ip.3322.net

# 3) 查在线会话（在线时应能拿到 userIp / userMac）
python eportal_login.py check --config config.local.json
```

认证成功后：**路由器自己就有网了**，之后连到它上面的任何设备都不需要再登录门户。

### Step 5 挂多台设备 —— 设备限制就在这里被解除

手机、平板、电脑、电视盒子……全部连路由器的 Wi-Fi/LAN 即可。它们不登录门户，校方侧看到的仍然是**路由器那一个 MAC**，账号的 2 设备配额只被占用 1 个。

即使你按 Step 3 之外的路径再去登录一次（比如让某台终端自己认证），也只占第 2 个名额 —— 所以**没必要**，别浪费。

### Step 6 掉线自动重认证（可选）

门户回执 `keepaliveInterval = 0`（不要求客户端保活），但网关仍可能因空闲/策略踢线。掉线后重新执行 Step 3 即可；想省事就让脚本盯着：

```bash
python eportal_login.py watch --config config.local.json --interval 60
```

Windows 上想开机自启，把这条命令塞进「任务计划程序」，或者在路由器上（若你的路由器支持脚本）用 `curl` 复刻同一套请求。

### Step 7（可选）电脑同时接了「手机共享 + 路由器」两条线怎么办

实测场景：电脑用 **手机 USB 共享**上网（默认路由优先级更高），同时网线又连着路由器。此时直接访问门户可能走的是手机那条路（到不了 `10.x` 内网）。

**不要**去删/改默认路由（那会真的断网）。用**绑定源地址**的办法，只让认证流量走路由器那条线：

```bash
# 192.168.31.247 = 电脑在路由器 LAN 侧的地址
curl --interface 192.168.31.247 -s -o /dev/null -w "%{http_code}\n" http://10.253.3.84/
python eportal_login.py login --config config.local.json --source-ip 192.168.31.247
```

`--source-ip` 只影响这个进程发出的包，**系统路由表一个字都不会动**，所以你正在用的那条网不受影响。

> Windows 小知识：想让电脑「优先走路由器」而不是手机，要么拔掉手机线，要么改网卡跃点
> （`ncpa.cpl` → 网卡属性 → IPv4 → 高级 → 取消「自动跃点」填 10；或管理员 PowerShell
> `Set-NetIPInterface -InterfaceIndex <序号> -InterfaceMetric 5`）。

## 5. 我们踩过的坑（省你时间）

| 现象 | 真实原因 | 解决 |
|---|---|---|
| 登录回 `密码不匹配,请输入正确的密码!` | 字段只编了一层 URL，服务端双重解码后拿到的是错的 | 所有字段双重 `encodeURIComponent`（脚本已处理） |
| 直接访问 `index.jsp` 回 `设备未注册,请联系管理员` | **不是**被封号：裸访问缺了门户下发的参数 | 带上 `wlanuserip/wlanacname/ssid/nasip/mac/t/url` 再访问 |
| 路由器后台报 `{"code":401,"msg":"Invalid token"}` | 小米后台的 `stok` 会话令牌过期（跟校园网认证无关） | 重新登录路由器后台，别在旧令牌上继续操作 |
| 用账号密码登录校园网失败 | 门户用的是**智慧校园统一身份**密码，不是路由器后台密码 | 去 `http://i.cqie.edu.cn/` 重置/确认 |
| 认证成功但某台设备上不了网 | 那台设备自己还开着校园网客户端/代理，或者 DNS 没走路由器 | 关掉终端上的认证客户端，DNS 交给路由器 |

## 6. 脚本

```
scripts/eportal_login.py       # 纯标准库，Windows/Linux 通用
scripts/config.example.json    # 复制成 config.local.json 填自己的账号（已在 .gitignore）
```

| 命令 | 作用 |
|---|---|
| `login` | 探测门户 → 登录认证，打印 `userIndex` 解码 |
| `check` | 查询在线会话（`userIp` / `userMac` / 门户公告） |
| `watch` | 轮询，掉线自动重新认证 |

参数：`--config`（配置文件）、`--source-ip`（多线路时绑定源地址）、`--interval`（watch 轮询秒数）。
也支持环境变量 `EPORTAL_ACCOUNT` / `EPORTAL_PASSWORD`，避免明文写进文件。

## 7. 风险与未验证项（诚实清单）

- **合规风险**：设备共享大概率违反校园网使用规定，风险自担；本仓库不提供任何规避校方审计的手段。
- **未验证**：校内是否部署 DPI 多设备检测、以及触发后的处罚形式，我们没有实测（原理与信号见 [docs/03](docs/03-detection-and-risks.md)）。
- **未验证**：门户升级/更换厂商后本文的接口与编码约定可能失效。
- **不涉及**：刷机/改固件（本方案不需要，也没写步骤）。
- 认证会话与 WAN 侧 MAC/IP 绑定：换路由器、恢复出厂后需要重新认证。
