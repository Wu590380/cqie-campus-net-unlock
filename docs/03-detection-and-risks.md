# 03 · 多设备检测的原理、信号与风险（本仓库不含刷机/固件步骤）

> 这一篇只讲**原理、现象和风险**，用于判断「NAT 方案为什么可能失效」。
> **不提供**刷机、改固件、装插件、绕审计的具体步骤 —— 那部分需要 OpenWrt 等第三方固件与专业操作，有变砖风险，也更容易踩线。

## 1. 为什么 NAT 有时「不隐身」

NAT 只改写了 **IP 层/传输层的地址**，但不同终端在**更高层**留下的痕迹是不一样的。校园网网关一旦做**深度包检测（DPI）/ 流量指纹分析**，就能从一条会话里看出「后面不止一台设备」：

| 检测维度 | 原理 | 典型差异 |
|---|---|---|
| **TTL** | IP 头里的 TTL 每过一跳减 1，不同系统初始值不同 | Windows 通常 128，Linux/Android 64，iOS 64 → NAT 后同一个 WAN 会话里出现 127 和 63 混用，立刻可疑 |
| **User-Agent / HTTP 指纹** | 报文里的 UA、Header 顺序、`Accept` 组合、HTTP/2 优先级 | 同一 IP 一会儿是 Android WebView、一会儿是 Windows Chrome |
| **TCP 时间戳 / IPID** | 各终端的内核时钟偏移、IP-ID 生成策略不同 | 同一会话里出现多套时钟斜率 → 多主机特征 |
| **并发连接与流量形态** | 同时几十个连接、多路视频、P2P | 单台设备的流量画像不可能同时像「下载机 + 手机 + 电视」 |
| **DNS / QUIC 特征** | 不同终端的 DNS 客户端、QUIC 版本/参数不同 | 一条 IP 上出现多种解析器指纹 |
| **802.1X 客户端特征** | （本环境不是这种，供对照）交换机侧看客户端类型/版本字段 | 仅在使用 802.1X 认证的校园网出现 |

## 2. 被判定的典型信号

如果你在做了 NAT 之后遇到下面这些现象，基本就是被 DPI 判了多设备：

- 认证成功后不久**又被踢回门户**，反复重新认证；
- 只有**部分设备**能上网，另一些（通常是电脑）被拦，提示类似「该终端类型不允许上网」；
- 速度被限、连接被重置，但重启路由器/减少设备后就恢复；
- 自助服务页里出现**你没登录过的设备记录**。

## 3. 公开研究里常见的对抗思路（原理层面）

> 以下只是**思路概览**，用于理解检测与对抗的博弈；本仓库不提供任何实现或固件操作步骤。

- **统一 TTL**：把 NAT 转发的报文 TTL 改写成一个固定值，抹掉「多系统 TTL 不同」这个最明显的信号。
- **统一 User-Agent（UA2F / UA3F 这类公开项目）**：在路由器上把 HTTP 请求头里的 UA 统一伪装成同一浏览器的标识，`UA2F` 使用 NFQUEUE 队列改包，`UA3F` 是它的用户态后继实现。
- **减少可分叉的行为**：关掉终端的 MAC 随机化、固定 DNS、避免在个别设备上跑 P2P/多线程下载、必要时限制并发连接。
- **克隆 MAC / 关闭 IPv6 的额外暴露面**：有些学校的策略是按 MAC 放行，或 IPv6 不做认证从而成为旁路特征。
- **让路由器自己成为认证主体**（就是本仓库的方案）：这一步是**前提**，只有先在网关侧建立「一台设备」的基线，上面这些「伪装成一台设备」的手段才有意义。

## 4. 本仓库的取舍与实测状态

| 事项 | 状态 |
|---|---|
| 单台终端 + 路由器 NAT | **已实测通过**，校方侧只记录 1 台设备 |
| 多台终端同时在线是否触发 DPI | **未验证**（我们没做这个实测，也不建议拿自己的账号去试探） |
| 刷机 / 改固件 / 装 UA2F 等 | **本仓库不提供**，超出「不刷机」的方案范围 |
| 门户换厂商/升级后 | 未验证，接口与编码约定可能失效 |

## 5. 合规与风险（务必自行判断）

- 用路由器共享一个账号给多台设备，**很可能违反学校《校园网用户协议》**，也可能违反运营商入网条款；
- 学校通常保留对网络流量做审计、限速、封停账号的权利，触发后的后果（断网、通报、纪律处分）由**使用者自己承担**；
- 上述对抗手段（改 TTL、伪造 UA 等）属于**规避网络管理措施**，性质比「单纯用路由器共享」更重，风险更高 —— 这也是本仓库只写在原理层面、不给步骤的原因；
- 校内资源（图书馆、教务等）本来就不需要认证，别为了这些去折腾。

## 6. 建议的做法

1. 先按 [README](../README.md) 的 NAT 方案走通，多数情况下这就够了；
2. 若出现第 2 节的信号，**先减少终端数量/关闭 P2P 试试**，确认是不是 DPI；
3. 真要长期多设备，**最稳妥的路是走学校/运营商的正规渠道**（例如办理允许更多终端的套餐或另一条独立账号线路）；
4. 无论做什么，别把账号密码交给任何第三方脚本或陌生工具 —— 本仓库的脚本只从你自己的配置文件/环境变量读凭据，也不会上传任何数据。
